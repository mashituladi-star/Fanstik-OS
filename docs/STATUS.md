# Текущее состояние Fanstik-OS

Дата обновления: 2026-11-27.

## Что реально работает

- Сборка PE/COFF UEFI-приложения для x86_64.
- Сборка freestanding ELF64-ядра с отдельным linker script.
- Генерация FAT32-образа ESP размером 64 MiB.
- Стандартный путь съёмной UEFI-загрузки `EFI/BOOT/BOOTX64.EFI`.
- Чтение `kernel.elf` через UEFI Simple File System Protocol.
- Проверка базовых ELF64-заголовков, program headers, границ файловых сегментов и исполняемой точки входа.
- Получение GOP, ACPI RSDP и карты памяти UEFI.
- Выделение фиксированных сегментов ядра и отдельного стека.
- Вызов `ExitBootServices` и передача `boot_info` в `RDI`.
- Ранняя диагностика через COM1.
- Host-side тест структуры `boot_info`.
- Smoke-тест загрузки в QEMU с OVMF до раннего цикла ядра.

## Что пока не реализовано

Ядро после проверки `boot_info` останавливается в цикле `cli; hlt`. Пока отсутствуют физический и виртуальный менеджеры памяти, GDT/IDT, обработчики прерываний, таймер, планировщик, user mode, системные вызовы, VFS, драйверы хранения, сеть, графический desktop, установщик и обновления.

Собственные расширения `.vyrka`, `.orveth`, `.sylqen`, `.drazik`, `.qelvar`, `.nethra`, `.aunvek`, `.moryth`, `.kavryn` и `.thavik` пока описаны документально и не являются рабочими бинарными форматами.

## Проверенные команды

```sh
make clean all test
OVMF_CODE=/usr/share/edk2/x64/OVMF_CODE.4m.fd \
OVMF_VARS=/usr/share/edk2/x64/OVMF_VARS.4m.fd make run
```

Для локального LLVM с нестандартным расположением библиотек может потребоваться `LD_LIBRARY_PATH`.

## Следующий приоритет

Следующий фундаментальный этап: сохранить карту памяти UEFI в типизированном интерфейсе ядра и реализовать ранний физический allocator страниц с тестами диапазонов. После него можно безопасно переходить к paging, GDT/IDT и таймеру.
