# Сборка и запуск

## Необходимые инструменты

Для сборки проекта требуются:

- Clang с поддержкой целей `x86_64-pc-win32-coff` и `x86_64-unknown-none-elf`;
- `lld-link` и `ld.lld`;
- GNU Make;
- хостовый C-компилятор для модульных тестов;
- для запуска в эмуляторе — `qemu-system-x86_64` и файлы UEFI-прошивки OVMF (образ кода и шаблон переменных).

Целевая система не использует среду выполнения какого-либо дистрибутива Linux. Хостовая ОС нужна только для разработки и сборки.

## Сборка

Открой терминал в корне репозитория и выполни:

~~~sh
make
make test
~~~

Результаты сборки:

- `build/BOOTX64.EFI` — приложение UEFI x86_64 для загрузки со съёмного носителя;
- `build/kernel.elf` — freestanding-образ ядра ELF64, который собирается отдельно.

UEFI-приложение и ядро остаются отдельными артефактами, но загрузочная цепочка уже соединена: загрузчик читает `kernel.elf` с ESP, проверяет ELF64, загружает его сегменты, получает `boot_info`, вызывает `ExitBootServices` и передаёт управление `_start` ядра.

## Собственные типы файлов Fanstik

Список необычных собственных расширений (.vyrka, .orveth, .sylqen, .drazik, .qelvar и другие), их назначение и правила безопасности описаны в [спецификации](FILE_FORMATS.md). Сейчас это документированная концепция: сборка пока выдаёт BOOTX64.EFI и kernel.elf, а бинарные форматы и загрузчики ещё не реализованы.

## Запуск в QEMU

Укажи переменную `OVMF_CODE`, содержащую путь к файлу кода UEFI-прошивки. При необходимости отдельно укажи `OVMF_VARS` — путь к шаблону хранилища переменных прошивки.

Пример:

~~~sh
OVMF_CODE=/usr/share/OVMF/OVMF_CODE.fd make run
~~~

Скрипт создаёт 64 MiB FAT32-образ ESP с файлами `EFI/BOOT/BOOTX64.EFI` и `kernel.elf`, создаёт рабочую копию хранилища переменных прошивки и запускает QEMU. Диагностические сообщения загрузчика и ядра выводятся через COM1 в консоль запуска.

Успешный smoke-тест QEMU должен завершаться строками `Fanstik-OS kernel entry reached.`, `Boot information validated.` и `Early kernel initialization complete.`. После этого ядро намеренно останавливается в цикле `cli; hlt`; полноценная инициализация памяти и планировщик ещё не реализованы.

## Возможные проблемы

- Если команда `clang` не найдена, установи Clang/LLVM.
- Если отсутствует `lld-link` или `ld.lld`, установи инструменты компоновки LLVM.
- Если QEMU не найден, установи эмулятор системы x86_64.
- Если OVMF не обнаружена автоматически, задай переменные `OVMF_CODE` и `OVMF_VARS` вручную.
- Если хостовый C-компилятор называется не `cc`, передай его имя через переменную `HOST_CC` в Make.

## Чистая пересборка

Чтобы удалить предыдущие результаты и собрать проект заново:

~~~sh
make clean
make
make test
~~~
