# Сеть и интернет — план реализации

> Сетевые функции пока запланированы. Наличие этого документа не означает, что Fanstik-OS уже подключается к интернету.

## Цель
После установки пользователь должен иметь возможность подключить поддерживаемый компьютер к Ethernet и получить настоящее сетевое соединение; Wi-Fi добавляется отдельно по мере готовности драйверов и безопасности.

## Последовательность реализации
1. PCI/device discovery и сетевой драйвер для виртуального NIC QEMU (virtio-net либо e1000 — определить по доступности и сложности).
2. MAC, отправка/приём Ethernet frames, буферы и обработка ошибок.
3. ARP и IPv4.
4. ICMP для диагностики.
5. DHCP: получение IP, netmask, gateway и DNS с проверкой аренды/таймаутов.
6. UDP и TCP; сокеты или согласованный network API.
7. DNS resolver.
8. Реальные тестовые соединения из QEMU (NAT/bridge), сетевые логи и диагностика.
9. GUI: статус, интерфейсы, IP, DHCP/DNS, connect/disconnect, reconnect, диагностика.
10. Ethernet-драйверы для реального оборудования; расширять список по тестам.
11. Wi-Fi: device discovery, scan, association, WPA2/WPA3 и безопасное хранение ключей только после необходимых драйверов и криптографических компонентов.

## Тесты и критерии
- Проверить обнаружение NIC и корректный MAC.
- Проверить отправку/приём frames в QEMU.
- DHCP получает реальный адрес от виртуальной сети.
- DNS разрешает реальное имя.
- TCP устанавливает соединение с тестовым endpoint.
- Проверить timeout, потерю соединения, отсутствие сети и повторное подключение.
- Все тесты должны иметь logs и чётко различать «пакет отправлен», «адрес получен» и «интернет-доступ подтверждён».
- Не показывать фиктивный статус «Connected» и не заявлять Wi-Fi поддержку без проверенного hardware/driver.

## Архитектурные требования
Разделить драйверы, Ethernet, IP, transport, DNS/DHCP, sockets/API, configuration и UI. Не связывать сетевую логику напрямую с desktop. Обрабатывать входные пакеты безопасно: проверять длины, checksum, переполнения и protocol state. Использовать проверенные криптографические решения для будущих защищённых протоколов, не создавать собственную криптографию.
